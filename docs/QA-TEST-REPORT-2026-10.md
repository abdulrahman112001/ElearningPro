## 0. الحالة بعد الإصلاح (الجولة الثانية)

أُصلحت كل الأخطاء الواردة في القسم 3، ما عدا البندين المذكورين في آخر هذا القسم. أُزيل وسم `@known-bug` من الاختبارات، فصارت تحرس من عودة الأخطاء.

| المجموعة | العدد | النتيجة |
|---|---|---|
| اختبارات الوحدة `npm run test:unit` | 37 | ✅ كلها ناجحة |
| اختبارات QA `npm run test:qa` | 202 | ✅ كلها ناجحة |
| اختبارات الصفحات `npm run test:e2e` | 70 | ✅ كلها ناجحة، 4 منها احتاجت إعادة محاولة لأسباب بيئية (انقطاع شبكة وبطء التجميع في وضع التطوير) |
| بناء الإنتاج `npm run build` | — | ✅ ناجح، و`tsc` و`next lint` بلا أخطاء |

أهم ما تغيّر:
- **أخطاء الـ 500:** معالج موحّد في `lib/api-error.ts` يحوّل JSON التالف وأخطاء Prisma المتوقعة إلى 400 أو 404 أو 409، في كل مسارات الـ API.
- **المال:** صرف أرباح المدرب أصبح آلة حالات ذرية، فلا صرف مزدوج. Stripe webhook أصبح idempotent بقيد `@unique` على `providerId`. الدفع غير المتاح يرجع 501، والإجمالي صفر يسجّل الطالب مباشرة.
- **الصلاحيات:** طلبات السحب للمدرب نفسه أو للأدمن فقط. البث المباشر للمسجلين فقط. لا يعدّل مدرب ترتيب أو اختبارات مدرب آخر. لا يراسل المستخدم الغرباء. الرفع محصور في مجلدات معروفة، والحذف للمالك فقط.
- **المصادقة:** حظر بعد 10 محاولات دخول فاشلة. الحظر وتغيير الدور يسريان فورًا. البريد لا يتأثر بحالة الأحرف. Rate limit لا يُخدع بترويسات مزيفة إلا خلف proxy موثوق (`TRUST_PROXY` أو Vercel).
- **التعلم:** الحد الزمني للاختبار يُفرض على الخادم. الدرس الذي فيه اختبار لا يكتمل إلا باجتيازه. الشهادة تتطلب اجتياز كل الاختبارات. الحفظ الدوري لا يلغي اكتمال الدرس.
- **النشر:** المدرب غير المعتمد يذهب إلى مراجعة الإدارة. أزرار القبول والرفض في لوحة الأدمن تعمل، وأُضيفت صفحة تفاصيل الدورة للأدمن.
- **الواجهة:** صفحات من نحن والمساعدة والأسئلة الشائعة والشروط والخصوصية. قائمة تنقل للجوال في لوحتي الأدمن والمدرب. المفضلة حقيقية مع API. الأسعار والمدد حسب اللغة. 404 حقيقي للدورة غير الموجودة. ترجمة النصوص الثابتة في نحو 25 ملفًا، و`aria-label` للأزرار الأيقونية، و`AlertDialog` بدل `confirm()`.
- **أخطاء hydration:** صفحة الشهادة وأرقام عدّاد الطلاب كانت تختلف بين الخادم والمتصفح.
- **البيئة:** `npm run db:seed` يعمل على Windows. البيانات التجريبية تنشئ ملفات المدربين. أُضيف ملف ESLint، و`next lint` بلا أخطاء. اختبارات `tests/e2e` تكتشف المعرّفات من القاعدة.

**ما لم يُصلح، ولماذا:**
1. **الرفع على القرص المحلي لا يعمل على Vercel.** الحل نقل الرفع إلى تخزين خارجي مثل UploadThing أو S3. هذا قرار بنية تحتية يحتاج اختيارك وبيانات اعتماد الخدمة.
2. **سباق استخدام الكوبون:** `usedCount` يزيد عند تأكيد الدفع فقط، فيمكن نظريًا فتح عدة جلسات دفع بالكوبون نفسه قبل اكتمال أي منها. الحل الكامل حجز الكوبون عند إنشاء الجلسة وتحريره عند انتهائها.
3. **انضمام أي مستخدم مسجّل لبث غير مرتبط بدورة** متروك عمدًا، لأنه يمثل بثًا عامًا (webinar).
4. **قاعدة الإنتاج في `.env` محذوفة.** تحتاج قاعدة جديدة ثم `prisma db push` و`npm run db:seed`.

## 1. كيف تُشغَّل الاختبارات

| الأمر | ماذا يختبر | يحتاج |
|---|---|---|
| `npm run test:unit` | المنطق النقي: التنسيق، Rate limit، توقيعات Paymob وTap | لا شيء |
| `npm run test:qa` | الـ API والصلاحيات والتجارة والاختبارات القصيرة والواجهة | Postgres محلي |
| `npm run test:e2e` | مجموعة الـ smoke القديمة في `tests/e2e` | انظر الملاحظة أدناه |

خطوات تجهيز قاعدة الاختبار:

```bash
# أي Postgres محلي بترميز UTF8
export QA_DATABASE_URL=postgresql://postgres:postgres@localhost:54329/elearning_test
DATABASE_URL=$QA_DATABASE_URL npx prisma db push
DATABASE_URL=$QA_DATABASE_URL npx ts-node --compiler-options '{"module":"CommonJS"}' prisma/seed.ts
npm run test:qa
```

ضمانات الأمان في مجموعة QA:
- ترفض العمل إذا لم تكن القاعدة على `localhost`.
- تشغّل الخادم بمفاتيح وهمية لـ Stripe وResend وPayPal وPaymob وTap وLiveKit، فلا يخرج بريد ولا عملية دفع.
- تحذف بياناتها السابقة في بداية كل تشغيل، أي المستخدمين `@qa.test` والكوبونات `QA-*`.

### ⚪ منخفضة: مدخلات خاطئة ترجع 500 بدل 400 أو 404

`AUTH-07`, `COM-19` (JSON تالف في كل المسارات) · `AUTHZ-08` (`?page=0`) · `LRN-14` (`answers` ليست مصفوفة) · `ADM-11` (دور غير صالح) · `ADM-12` (معرّف غير موجود) · `ADM-21` (رسالة لمستخدم غير موجود) · `COM-43` (تقييم 4.5 يُقبل)

### مكتشفة بالمراجعة، دون اختبار آلي

- `POST /api/upload` يبني المجلد من حقل `type` دون تنقية، فيمكن الكتابة خارج `public/uploads` (path traversal). لم يُختبر عمدًا كي لا تُكتب ملفات داخل المشروع.
- الرفع على القرص المحلي لا يعمل على Vercel.
- `DELETE /api/upload` بلا فحص ملكية.
- Webhook الخاص بـ Stripe: إذا كان المستخدم مسجلًا مسبقًا يرجع 500 دائمًا، فيعيد Stripe المحاولة إلى ما لا نهاية.
- `providerId` ليس `@unique`.
- أزرار قبول ورفض الدورات والمدربين في لوحة الأدمن الرئيسية بلا `onClick`.
- 29 مفتاح ترجمة مفقود، ونصوص عربية ثابتة في نحو 15 مكوّنًا.
- 4 استخدامات لـ `confirm()` الأصلي، ونحو 49 زر أيقونة بلا `aria-label`.

## 4. ما يعمل بشكل صحيح (169 حالة ناجحة)

- **الصلاحيات:** كل مسارات الأدمن والمدرب ترفض المجهول (401) والطالب والمدرب حسب الدور. الصفحات المحمية تحوّل للدخول.
- **عزل الدورات:** مدرب لا يعدّل أو يحذف أو ينشر دورة غيره، ولا يضيف فصلًا لها، ولا يعدّل دروسها.
- **التسجيل:** لا يمكن طلب دور ADMIN. الـ profile لا يغيّر الدور أو البريد. التحقق من البريد وطول كلمة المرور يعمل.
- **التجارة:** لا تسجيل مجاني في دورة مدفوعة (402). الكوبونات: منتهي، غير نشط، مستنفد، حد أدنى، مرتبط بدورة أخرى، سقف الخصم، الخصم لا يتجاوز السعر. توقيع Stripe webhook مطلوب.
- **الاختبارات القصيرة:** الإجابات الصحيحة لا تُسرَّب للطالب، لا في الـ API ولا في HTML الصفحة. التصحيح على الخادم صحيح للاختيار الواحد والمتعدد. لا تسليم مرتين، ولا تسليم محاولة شخص آخر.
- **الشهادات والتقييمات:** الشهادة مرفوضة قبل الإكمال. التقييم يتطلب التسجيل، وتقييم واحد لكل مستخدم.
- **الواجهة:** الصفحات العامة تعمل دون أخطاء JS، واتجاه `dir` يتبدل بين ar وen.

## 5. ترتيب الإصلاح المقترح

1. **فورًا:** AUTHZ-04 وADM-02 وADM-03 وCOM-33 وOWN-07 وLRN-22، ثم path traversal في الرفع.
2. **هذا الأسبوع:** Rate limit للدخول مع إصلاح `getClientIp`، وإنهاء جلسة المحظور، وOWN-06، وموافقة المدرب قبل النشر، والحد الزمني للاختبار القصير، وAUTH-20، والمفضلة.
3. **بعد ذلك:** التحقق من المدخلات بـ zod لإنهاء أخطاء الـ 500، وتوطين `formatPrice`، والروابط المكسورة، ومفاتيح الترجمة، وقائمة الجوال.
4. **بنية تحتية:** قاعدة إنتاج جديدة، وإصلاح `db:seed` وإضافة `InstructorProfile` له، وإضافة ESLint، وتحديث `tests/e2e/api.spec.ts`.

بعد كل إصلاح، يتحول الاختبار الموسوم `@known-bug` المقابل من الفشل إلى النجاح.
