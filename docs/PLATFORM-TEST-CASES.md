# حالات اختبار منصة ElearningPro

الوثيقة دي بتحوّل رحلات المنصة الأساسية إلى حالات اختبار قابلة للتنفيذ يدويًا أو بـPlaywright. التغطية مركزة على الطالب، وتشمل المعلم والمدير وولي الأمر، مع اختبارات تربط الأدوار ببعض.

> **مهم:** دي حالات مطلوبة للاختبار، مش تأكيد إن كل ميزة مكتملة أو إن الحالات دي اتنفذت. قبل التشغيل، جهّز قاعدة اختبار محلية منفصلة وبيانات تجريبية؛ ما تستخدمش قاعدة الإنتاج أو قاعدة مشتركة مع الـagents. اختبارات `tests/qa` الحالية بتنشئ وتحذف بيانات اختبار.

## طريقة قراءة الحالات

- **P0:** مسار أساسي أو أمان/فلوس/درجات؛ لازم ينجح قبل الإصدار.
- **P1:** وظيفة رئيسية أو حالة خطأ مهمة.
- **P2:** تجربة استخدام، توافق، أو حالة طرفية.
- كل حالة بتحدد الشرط المسبق، الإجراء، والنتيجة المتوقعة. استخدم حسابات وبيانات اختبار مصطنعة فقط.
- الحالات الموسومة «تحقق من السياسة» تحتاج تثبيت قاعدة العمل أولًا، مثل عدد محاولات الامتحان أو مهلة تسليم الواجب.

## تجهيز بيئة الاختبار

1. شغّل التطبيق على بيئة محلية أو staging مع قاعدة بيانات مخصصة للاختبارات.
2. جهّز حسابات طالب، معلم معتمد، مدير، وولي أمر، بالإضافة لحسابات غير مسجلة/غير مسجلة في مقرر.
3. جهّز مقررًا مجانيًا وآخر مدفوعًا، دروس فيديو ومحتوى، امتحانًا بأنواع أسئلة مختلفة، واجبًا، فصلًا/مجموعة، ورصيد محفظة ورموز شحن اختبارية.
4. استخدم بوابات دفع وواتساب وذكاء اصطناعي وهمية أو وضع تسجيل محلي؛ ممنوع إرسال أموال أو رسائل حقيقية.
5. في كل اختبار صلاحيات، جرّب واجهة المستخدم والـAPI مباشرة؛ إخفاء الزر وحده لا يثبت حماية المورد.
6. عند الفشل، احتفظ بـtest ID، الطلب/الاستجابة بعد حذف أي بيانات شخصية، screenshot، وtrace.

| GEN-06 | P1 | زائر | سجّل حسابًا ببريد مستخدم بالفعل. | رفض التسجيل بدون تكرار المستخدم أو تسريب بياناته. |
| GEN-07 | P1 | مستخدم | أرسل JSON تالفًا أو حقولًا بأنواع غير صحيحة إلى APIs التسجيل/تعديل الملف. | استجابة 4xx مفهومة، لا 500 ولا تغيير جزئي للبيانات. |
| GEN-08 | P0 | مستخدم | سجّل الخروج ثم أعد استخدام cookie/session قديمة لطلب محمي. | تُرفض الجلسة بعد تسجيل الخروج. |
| GEN-09 | P0 | كل الأدوار | حاول استدعاء endpoint خاص بدور آخر مع جلسة صحيحة. | 403/404 حسب العقد، ولا يحدث تغيير أو تسريب بيانات. |
| GEN-10 | P0 | مدير | احظر مستخدمًا مسجلًا ثم اطلب منه فتح صفحة وAPI محميين. | يُمنع الحساب حسب سياسة الحظر، وتُلغى/تُرفض الجلسة المحمية. |
| GEN-11 | P1 | مستخدم | اطلب موردًا بمعرّف غير موجود أو بمعرّف مستخدم آخر. | 404/403 آمنة، لا بيانات لطرف آخر ولا خطأ داخلي مكشوف. |
| GEN-12 | P1 | مستخدم | أرسل قيمًا طويلة جدًا، HTML/سكريبت، أو رموزًا غير متوقعة في الاسم والبحث والرسائل. | التحقق والتعقيم يعملان؛ لا XSS ولا كسر للصفحة أو قاعدة البيانات. |
| GEN-13 | P1 | مستخدم | كرر طلبًا حساسًا بسرعة، مثل التسجيل أو بدء امتحان، بعد تجاوز حد المعدل. | استجابة 429 مناسبة، ولا تتكرر العملية أو تُنشأ سجلات زائدة. |
| GEN-14 | P2 | طالب/معلم/مدير | بدّل اللغة العربية والإنجليزية، وافتح صفحات الدور على شاشة هاتف. | اتجاه RTL/LTR والنصوص صحيحان، ولا توجد مفاتيح ترجمة ظاهرة أو تمريرات أفقية غير مقصودة. |

## 13. معايير نجاح الأتمتة

- حالات **P0** كلها ناجحة قبل الإصدار، خصوصًا الوصول، ملكية الموارد، الدفع والمحفظة، الامتحانات، الربط الأسري، وتحقق الشهادات.
- الحالات السلبية تتحقق من عدم حدوث أثر جانبي، وليس من status code فقط.
- اختبارات المال والرموز والمحاولات المتزامنة تتحقق من سجلات قاعدة البيانات بعد الطلب.
- بيانات الاختبار قابلة لإعادة التشغيل والتنظيف، ولا تعتمد على ترتيب عشوائي أو خدمة خارجية حقيقية.
- أتمتة Playwright تغطي رحلات UI الأساسية، وAPI/DB assertions تغطي الصلاحيات والآثار الجانبية؛ لا تستخدم screenshots وحدها كمعيار نجاح.
- لا تعتبر حالة «تحقق من السياسة» ناجحة حتى يتم توثيق قاعدة العمل المتفق عليها وربط التوقع بها.

## 14. تغطية الأتمتة الموجودة حاليًا

أسماء suites الموجودة وقت كتابة الوثيقة: `01-auth`, `02-authorization`, `03-ownership`, `04-commerce`, `05-learning`, `06-admin-money`, `07-ui`, `08-fixes`, `09-scenario`, `10-new-pages`, `11-instructor-application`، بالإضافة إلى `20-video-protection`, `21-codes-wallet`, `23-parents`, `25-attendance-fees`, `26-school`, `27-ai`.

اختبارات الوحدات منفصلة في `tests/unit`. وجود ملف اختبار لا يعني أنه اجتاز التشغيل. اختبارات QA تستخدم قاعدة بيانات محلية وتكتب بيانات؛ شغّلها فقط بعد التأكد أن قاعدة الاختبار منفصلة وأن لا agent آخر يستخدم السيرفر/البيانات نفسها. الميزات التي ليس لها suite ظاهر هنا، مثل الواجبات/كشف الدرجات، النقاط/PWA والامتحانات المتقدمة كميزة مستقلة، تحتاج تغطية مخصصة أو تأكيد أن اختبارات أخرى تغطيها.
